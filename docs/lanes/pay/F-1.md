# F-1 (F2a): staff enter pay lines into a transfer (R3)

Draft from legacy code, 2026-11-05. Legacy source: `/home/user/studenthub` (master). Line numbers as read in this pass.

## Outcome (contract)
Staff create a transfer for a company and period, add lines per person (amount, hours or units, note) with exact decimal arithmetic and integer minutes, see totals per currency, and lock it. Every line edit audited. The person sees "Pay" on My profile with their own lines once locked.

## Rules (with legacy citations)
1. Payable line: at least one of hours, minutes, seconds, bonus is > 0 (line 1073). Otherwise the calculator returns an error-shaped array with zero totals (lines 1077-1080).
2. Hourly/unit path total: `candidate_total = bonus - bonus_commission + hours*candidate_hourly_rate + minutes*minute_rate + ...`; `company_total = bonus + hours*company_hourly_rate + minutes*company_minute_rate + ...` (lines 1384-1392).
3. Monthly salary path (`Contract::TYPE_MONTHLY_SALARY`, line 1328): `candidate_total = contract.amount.candidate_total / $noOfPayout`, same for company (lines 1332-1334). If the value carries `company_total > 0`, candidate total is scaled by `value.company_total / company_total` and the company total is replaced (lines 1338-1341).
4. Fixed price path (line 1344): totals are the contract amounts as-is (lines 1349, 1351).
5. Zero company total is rejected (line 1397).
6. Zero bonus commission and zero company hourly rate with a parent company: parent values are used (lines 1298-1310); with no parent and both zero, error (lines 1360-1361).
7. Contract date range must cover transfer dates (`Transfer::validateContract`, `common/models/Transfer.php:101-119`).
8. Errors come back as arrays with `operation` keys, not exceptions (for example lines 1053, 1077, 1122, 1140, 1160, 1196, 1202, 1234).

## Edge cases (legacy behaviour)
- Floats throughout. `(float)`/`(double)` casts (lines 1068-1071, 1169, 1332, 1349, 1372-1376) and PHP `round(x, 3)`. Money is not exact decimal. The contract asks for exact decimal; the benchmark rule says reproduce legacy results to the fils (decisions file, SHU-208). Conflict to settle in the replay: decimal ROUND_HALF_UP vs PHP `round()` (half away from zero). They differ on exact .0005 ties. Test those cases explicitly.
- `minutes` is cast to int, so fractional minute input truncates silently (line 1182). `seconds` is folded into hours, so the stored hours value can carry fractions that round at the line level.
- `hours` is cast with `(float)` before `$value['hours'] ?? 0`; a non-numeric string becomes 0 and the line is then "not payable" rather than rejected.
- Monthly path ignores the line's own hours and bonus (line 1328 branch); a monthly line with bonus is not added.
- `saveCandidateTransfer` is per candidate; a failed candidate returns an error array and the caller decides whether the whole batch continues (check `saveTransfer` loop, not fully read).
- Multi-currency: totals are per transfer currency; the contract wants totals per currency, legacy shows one currency per transfer (`Transfer.currency_code`).
- Store/company snapshot is copied at line time (`store_name`, `company_name`, `company_email`). Later renames do not propagate.

## Test cases
1. Hourly: hours=2, minutes=30, seconds=0, rate=5.000 -> candidate_total = 12.500 (2.5 h * 5).
2. Seconds folding: hours=0, minutes=0, seconds=1800 -> hoursFloat 0.5; total equals 0.5 * rate.
3. Bonus with commission: bonus=10, commission 10% -> bonus_commission=1.000, candidate total = 10 - 1 + hours*rate.
4. Payable gate: all zero -> error array, no line created (matches line 1073/1077).
5. Monthly: amount 400.000, noOfPayout 4 -> candidate_total 100.000 per payout (line 1332).
6. Monthly with company override: company_total override 50 against contract company_total 100 -> candidate total halved proportionally (line 1338-1341).
7. Fixed price: totals equal contract amounts regardless of hours (line 1349).
8. Parent rate fallback: company commission 0 and hourly rate 0, parent has rate -> parent values used.
9. Rounding replay: a fixture set of at least 200 real legacy lines (from the replay, not invented) must match `candidate_total`/`company_total` to 3 dp, including the .0005 tie cases.
10. Minutes int: minutes=30.7 stored as 30 (matches legacy) or rejected (decide; record in the contract).
11. Line outside contract dates -> validation error (Transfer::validateContract).
12. Candidate not assigned to the company in the period -> line refused (see F-3 lock check; the create path must also refuse).
13. Locked transfer: no line edit allowed (legacy enforces via status? not verified; add a test against legacy behaviour before assuming).
14. Person's own view after lock: only lines with paid=1 and transfer status Distributing or Complete appear (candidate `actionSalary` line 811), which conflicts with the contract text (see below).
