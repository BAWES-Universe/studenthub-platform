## Lock guard and child creation (Draft → Locked)
- `lock()` (common, line 1080): refuses if any transfer candidate's `candidate_id` is not in `$this->company->getCandidates()` (the company's current candidates). Message lists the candidate ids. The user must delete and recreate.
- Then `generateEachCompanyTransfer()` (line 990): if the company has sub-companies and candidates span them, `generateSubCompanyTransfer` (line 877) creates a child transfer per sub-company (`parent_transfer_id`, one per company; `findOne` reuse if it exists). Otherwise `generateTransferInvoice()` (line 972) creates one invoice (`findOne(['transfer_id'])` check, then insert with status `unpaid`).
- No DB transaction wraps `lock()`. A failure after child creation leaves children and status still Draft. The contract wants zero effects on late failure. Legacy does not have this.
- Exactly-once: the invoice has a `findOne` check, which is not safe under concurrent requests (no unique key verified). Child transfer creation has the same check.

## Edge cases
- A transfer can be deleted from Locked after children and invoices exist. Soft deletes cascade, so the invoice is hidden, but a paid child transfer is not guarded.
- `paymentSent()` and `cancel()` throw `\Exception` (plain PHP), not a domain error type; callers wrap them.
- Mark-unpaid after Complete moves the whole transfer back to Distributing (`admin/models/TransferCandidate.php:113-115`), which can re-open the invoice flow implicitly.
- `unlock()` from Payment Sent is allowed, which means a paid-sent transfer can return to Draft and regenerate nothing (children and invoices stay). Check the rebuild rule.
