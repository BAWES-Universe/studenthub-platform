## Summary — highest-value frontend-only findings (10 lines)

1. Client calls seven endpoints that are unroutable at c2ce255 (`enableStrictParsing`): all `/invitations/*` (invite, by-otp, accept, reject, delete, list), `POST /auth/login-by-apple`, `DELETE /company-contacts/<id>`, `PATCH /requests/cancel|deliver` — team invitations, legacy OTP registration and member removal are dead end-to-end (EMP-FO-03/06/07/12).
2. Work-log approval state machine lives only in the client: `status` 1/2, `rating`, `reason`, `is_public` are chosen by the UI and the server stores whatever arrives, with no transition check and no ownership check on single-session `POST /candidate-work-log-feedbacks` (EMP-FO-22..25; confirms WK-F4).
3. `GET /aws/config` hands the browser a static access key/secret used for `public-read` uploads to a 24-hour bucket; logo/licence/Excel imports depend on it (EMP-FO-30; OP-05/OP-F1 confirmed).
4. Employer candidate view renders civil-ID number, expiry and front/back images plus resume/video from public S3 URLs; server strips documents when the candidate is not in a managed store but returns civil-ID number, birth date and video for **any** candidate id (EMP-FO-19/20; PD-05/PD-F5 for the SHU-200 decision).
5. No role/permission model exists in the client: every org member sees company edit, team removal, transfers, approvals; the only server-side role check (`currentUserRole != 'Owner'`) references an undefined property (EMP-FO-05/06; ID-F4 confirmed for the employer app).
6. Multi-company binding is client-driven: `companies[0]` fallback + `Company-ID` header; the server validates the header, so OR-18 "does not exist in legacy" should read "exists as header selection with no server context" (EMP-FO-04, OR-F3).
7. `company_status_override == 9` (under review) only triggers a client redirect from the tab shell; no employer API action is blocked server-side except candidate invitations via `company_approved_to_hire` (EMP-FO-38).
8. reCAPTCHA v3 is executed in the browser and ignored by the server (verification commented out) — there is no login throttle (EMP-FO-01; ID-F7).
9. Algolia CV search, candidate list, company list, interview scheduling, request cancel/deliver, fixed/monthly transfer forms and the invite-staff modal are orphaned or placeholder screens — the secured-key search (RC-04/RC-F3) is not reachable in this build (EMP-FO-18/29, B orphans).
10. Transfer totals and the 180-hour sanity check are client computations in floating point; the server recomputes the same way, so the exact-decimal requirement (F2) has no client dependency to preserve (EMP-FO-27).
