## Summary — highest-value frontend-only findings

1. Permission model is entirely client-side: 7 keys (`company-stats/contracts/transfers/activity/notes/contact-login`, `candidate-financials`) gate tabs/buttons in the UI; backend reads `PermissionUser` only in `PermissionSectionController` — SHU-124 F4 confirmed for the staff app (FO-02..09).
2. `hasPermission` is default-allow for company-specific sections (`permission.service.ts:35-41`), and a failed permission fetch logs the user in with an empty map — gates fail open.
3. Login-as (candidate, contact, store manager) is available to any authenticated staff server-side; the UI gate exists on one of four buttons only (FO-04, ID-17/PD-37).
4. `GET /aws/config` is unauthenticated and hands out a static AWS key/secret; the app calls it without a bearer token (FO-32, OP-05/SHU-134).
5. Algolia secured key has no `validUntil` (commented out) and the browser queries the index directly; key is cached until a 400 (FO-31, RC-F3).
6. Request status transitions (`re_work`, `finished_by_recruitment`, cancel, deliver) are chosen in the client; server validates values, not transitions (FO-12, RC-F4); same pattern for appeal status (FO-16, WK-F4), suggestion accept/reject (FO-19) and ticket status (FO-22).
7. `role` from the login response gates Assign/Update on requests client-side only; backend has no role check on `/requests/assign` or `/requests/{id}` (FO-10).
8. Commercial terms and contract rates are writable by any staff; `actionAssign` saves with `save(false)`, no positivity rule on rates (FO-11, FO-15).
9. Transfer locking/advance is correctly server-enforced (FO-13/14) — the client status gates there are UX only; totals and rates are recomputed server-side.
10. Broken/dead paths: expense edit (`PATCH /staff-expenses/{id}` has no backend route), `interview-evaluation addNewVersion` verb mismatch, `story/current-story` missing, store-assignment-request accept never wired, `candidate-update-email` and `upload-cv`/`location` call non-existent `AccountService` methods, dashboard "minors" filter ignored; POST/PATCH calls are retried up to 3× on 5xx/timeouts with no idempotency (FO-36).
